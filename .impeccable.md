# ATC — Actions Traffic Control

## Design Context

### Users
DevOps engineers, platform engineers, and engineering managers monitoring GitHub Actions workflows across multiple orgs and repos. They open ATC when they're waiting on CI, debugging a stuck queue, or checking whether self-hosted runners are saturated. Context is usually: "something might be wrong" or "I'm waiting and want to know why." Wall displays in team areas are a secondary use case — the dashboard should be legible at distance but is primarily used at a desk.

### Brand Personality
**Playful technical** — like Linear or Raycast. Polished, fast, keyboard-first, with personality in transitions, empty states, and micro-interactions. The ATC/aviation metaphor provides the thematic backbone but should feel like a nod, not a costume. Confidence without severity.

Three words: **precise, animated, confident.**

### Emotional Goals
- Opening the dashboard should feel like opening a well-made instrument — satisfying, not stressful
- Failures should be unmistakable but not alarming (this is CI, not life-or-death ATC)
- Empty/idle states should feel calm and intentional, not broken
- Transitions should feel responsive and physical (spring/ease-out, not linear)

### Aesthetic Direction

**Visual tone**: Dense and data-forward (Grafana), bold status-color-on-dark (Concourse CI), with the polish and animation quality of Linear. Dark mode is primary; light mode is supported.

**References**:
- **Grafana** — muted dark backgrounds, bright semantic colors for status, information density without clutter
- **Concourse CI** — pulsating halos for running state, bold color blocks, "information ruthlessness"
- **Linear** — buttery 60fps animations, strong typography hierarchy, keyboard-first interactions, premium developer-tool feel

**Anti-references** (explicitly avoid):
- **Jenkins** — no cluttered tables, no 2008-era Java web UI, no information overload without hierarchy
- **GitHub Actions UI** — no nested drill-down mazes, no per-repo silos, no "click 4 times to find the failure"
- **Generic SaaS dashboards** — no card-heavy marketing layouts, no pastel illustrations, no rounded-everything "enterprise feel"

**Theme**: Dark-first with OKLCH-based layered backgrounds. 4 user-selectable neutral hue themes (Warm, Radar, Violet, Pink). Status colors are the only high-chroma elements on screen. Light mode inverts the surface layers and uses darker status color variants for contrast.

### Design Principles

1. **Information ruthlessness** — Every pixel must help the user triage. If a piece of information doesn't help answer "what's broken?" or "why is this slow?", cut it. Inspired by Concourse CI's philosophy.

2. **Color + symbol duality** — Never encode meaning with color alone. Every status has a unique color AND a unique symbol. Derived from 70+ years of ATC human factors research and critical for accessibility.

3. **Motion with purpose** — Animations serve comprehension (state transitions, progressive disclosure) or delight (micro-interactions, empty states), never decoration. Pulsating halos on running jobs are functional — visible across a room. All motion respects `prefers-reduced-motion`.

4. **Progressive disclosure** — Show the minimum by default, reveal detail on demand. Compact cards (icon + name + duration) for scanning, expanded cards (steps, runner, branch) for debugging. The user controls the density.

5. **Keyboard-first, mouse-friendly** — Like Linear: everything reachable via keyboard, but mouse/touch works naturally too. No mode where keyboard users are second-class.

### Accessibility

- **WCAG AAA compliance** target — 7:1 contrast for normal text, 4.5:1 for large text
- **Reduced motion**: Respect `prefers-reduced-motion` media query. Pulsating halos, state transitions, and all animations must degrade gracefully to instant state changes
- **Color + symbol duality**: Already core to the visual language — no status is communicated by color alone
- **Focus indicators**: Visible, high-contrast focus rings on all interactive elements
- **Screen reader support**: Semantic HTML, ARIA labels for status indicators, live regions for real-time updates

### Color System — OKLCH

The entire neutral ramp is derived from a single `--hue` CSS variable. Switching
themes changes one value; all surfaces, text, and borders recompute automatically.

#### Type Scale

Major Third (1.25) scale rooted at `0.75rem`. Three active sizes plus logo:

| Token        | Size       | Weight   | Role                                         |
|--------------|------------|----------|----------------------------------------------|
| `--text-xs`  | 0.625rem   | 400      | Uppercase labels, meta, runner info, buttons  |
| `--text-sm`  | 0.75rem    | 400      | Card data, controls, duration, prompt text    |
| `--text-base`| 0.9375rem  | 600      | Job names, status icons — primary card content|
| `1rem`       | 1rem       | 700      | Logo only                                     |

Line heights: `--leading-tight: 1.2` (headings, labels), `--leading-normal: 1.5` (body),
`--leading-relaxed: 1.6` (prose like prompt text).

Letter spacing: `--tracking-tight: -0.01em` (job names), `--tracking-normal: 0`,
`--tracking-wide: 0.1em` (uppercase labels).

All monospace data values (durations, step counts, runner counts) use
`font-variant-numeric: tabular-nums` to prevent layout jitter as digits change.

#### Themes

| Name   | Hue | Personality                              |
|--------|-----|------------------------------------------|
| Warm   |  70 | Inviting, premium, Linear-like           |
| Radar  | 155 | CRT phosphor green, leans into ATC metaphor |
| Violet | 280 | Modern dev tool feel (VS Code, Warp)     |
| Pink   | 310 | Playful, warmer purple, distinctive      |

Base chroma: **0.060**, tapered across lightness to keep dark surfaces richly
tinted while light surfaces stay clean.

#### Semantic Tokens (Dark Mode)

```css
/* Theme hue — the only variable that changes between themes */
--hue: 155; /* radar (default) */

/* Neutral surfaces — all derived from --hue */
--bg:              oklch(12% 0.063 var(--hue));   /* deepest background */
--surface:         oklch(16% 0.063 var(--hue));   /* card/panel surfaces */
--surface-raised:  oklch(20% 0.060 var(--hue));   /* inputs, recessed elements */
--border:          oklch(25% 0.055 var(--hue));   /* subtle borders */

/* Neutral text — also derived from --hue */
--text:            oklch(85% 0.028 var(--hue));   /* primary text, ~12:1 AAA ✓ */
--text-dim:        oklch(72% 0.030 var(--hue));   /* secondary text, ~7.8:1 AAA ✓ */

/* Status colors — fixed hues, independent of theme */
--queued:          oklch(72% 0.15 250);           /* blue, 7.7:1 AAA ✓ */
--running:         oklch(78% 0.16 80);            /* amber, 9.4:1 AAA ✓ */
--success:         oklch(72% 0.16 155);           /* green, 8.2:1 AAA ✓ */
--failed:          oklch(72% 0.17 25);            /* red, 7.1:1 AAA ✓ */
--cancelled:       var(--text-dim);               /* neutral, follows theme */

/* Accent (for buttons with white text) */
--accent:          oklch(45% 0.20 250);           /* deep blue, 7.2:1 AAA ✓ */

/* Typography */
--font: -apple-system, BlinkMacSystemFont, 'Segoe UI', system-ui, sans-serif;
--mono: 'SF Mono', 'Fira Code', 'Cascadia Code', monospace;
```

#### Semantic Tokens (Light Mode)

```css
/* Surfaces flip to high lightness */
--bg:              oklch(97% 0.022 var(--hue));
--surface:         oklch(99% 0.013 var(--hue));   /* tinted white, not pure white */
--surface-raised:  oklch(92% 0.025 var(--hue));
--border:          oklch(85% 0.028 var(--hue));

/* Text flips to low lightness */
--text:            oklch(16% 0.063 var(--hue));   /* ~18:1 AAA ✓ */
--text-dim:        oklch(40% 0.040 var(--hue));   /* ~8.9:1 AAA ✓ */

/* Status colors — darker variants for light backgrounds */
--queued:          oklch(45% 0.18 250);           /* 7.1:1 AAA ✓ */
--running:         oklch(45% 0.15 80);            /* 7.4:1 AAA ✓ */
--success:         oklch(42% 0.15 155);           /* 7.3:1 AAA ✓ */
--failed:          oklch(48% 0.18 25);            /* 7.0:1 AAA ✓ */
--cancelled:       var(--text-dim);

/* Accent stays the same — works on both */
--accent:          oklch(45% 0.20 250);
```

#### Theme Switcher

```css
[data-theme="warm"]   { --hue: 70; }
[data-theme="radar"]  { --hue: 155; }
[data-theme="violet"] { --hue: 280; }
[data-theme="pink"]   { --hue: 310; }
```

|------|-----------|--------|--------|-------------|--------------|

| n-2  | 16%       | 0.063  | 1.05   | --surface   | --text       |

| n-4  | 25%       | 0.055  | 0.92   | --border    | —            |
| n-5  | 35%       | 0.050  | 0.84   | —           | —            |
| n-6  | 40%       | 0.040  | 0.74*  | —           | --text-dim   |
| n-7  | 55%       | 0.040  | 0.66   | muted/decorative | —      |
| n-8  | 65%       | 0.035  | 0.58   | —           | —            |
