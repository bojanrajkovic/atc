# CLAUDE.md — atc-server

Last verified: 2026-05-15 (post hot-reload landing)


> Canonical documentation lives in `docs/architecture/backend-server.md`. This file provides crate-specific guidance for agents working here. Do not duplicate content from the architecture doc.

## Purpose

Axum HTTP server wiring `atc-core` (pure transition functions) and `atc-github` (webhook parsing) together. Provides HTTP endpoints for webhook ingestion, REST state snapshots, and WebSocket event streaming. The only executable crate in the backend workspace. **State persistence concerns are split across crates**: the in-memory backend lives in `atc-store-mem` (`InMemoryStore`); the PG backend (`PgStore` — outbox/drain/eviction/snapshot reads) is hosted in-tree at `atc-server::persist` until its dedicated `atc-store-pg` crate lands. Both the webhook write path AND the `/v1/state` read path AND `/readyz` dispatch through `AppState.persist: Arc<dyn PersistentStore>`. See ADR 0005 (write-path trait relocation), ADR 0008 (persistence crate split), and issue #69 (read-path unify + atc-core purification).

## Storage modes

Two runtime modes. Only external Postgres is production-supported — see `docs/architecture/backend-server.md` § "Storage modes — operator guidance" for the canonical write-up.

- **External Postgres** (`ATC_DATABASE_URL` set) — required for `replicaCount > 1` (chart guard refuses to render otherwise). The drain task is the sole broadcaster.
- **In-memory** (`ATC_DATABASE_URL` unset) — **dev-only**, single-replica only. Useful for `just dev` against curl/smee.io-fired webhooks; lossy on restart; do not deploy to production. `InMemoryStore` (from the `atc-store-mem` crate) owns the seq mutex internally and broadcasts via `webhook_tx` inside `apply_*_event`. Eviction task is spawned only in this mode.

## Modules

| Module | Role |
|--------|------|
| `main` | Entry point, config loading, AppState creation (6 fields: `persist`, `webhook_secret`, `runner_pool_capacities` (lock-wrapped), `config_events_tx`, `shutdown`, `ws_tracker`), router setup, lifecycle. `Config::runner_pools` is `Vec<RunnerPoolCapacity>` directly (figment deserializes YAML into the domain type), so `initial_capacities` is built by a direct move with no mapping step; the `config_events_tx` channel and `config_watcher::spawn_config_watcher` are wired here, with the returned `Option<JoinHandle<()>>` passed into `run_shutdown_orchestration`. Constructs the active `Arc<dyn PersistentStore>` via `atc_store_pg::PgStore::start` (PG mode) or `InMemoryStore::start` (in-memory mode); the per-store background tasks are spawned and owned by the store itself (ADR 0006). Imports `atc_store_pg::{db, listener, DbInitError, PgStore}` for the PG-mode branch; the migration-vs-connect discriminator at the `init_pool` call site matches on `DbInitError::Migrate(_)` rather than `sqlx::Error::Migrate(_)`. |
| `config` | figment-based `Config` chained `defaults → Yaml::file($ATC_CONFIG_FILE | "/etc/atc/config.yaml") → Env::prefixed("ATC_").split("__")`. Carries `GitHubConfig` and operator-declared `runner_pools: Vec<RunnerPoolCapacity>` (file-only; figment deserializes YAML directly into `atc_core::RunnerPoolCapacity` — no separate loader-side mirror type). `RunnerPoolCapacity`'s struct-level custom `Deserialize` enforces explicit key presence and rejects unknown fields, distinguishing `capacity: null` (→ `None`, unbounded) from key omission (→ error: `"capacity is required (use \`capacity: null\` for an unbounded pool)"`). `LabelSet` (BTreeSet under the hood) canonicalizes labels (sort + dedup) during deserialization, so no separate canonicalize step is needed. `database_listener_url` falls back to `database_url` at runtime. Post-extract validation (`validate_capacities`, shared between startup and hot-reload) is a pure scan: rejects `Some(0)` (with `"capacity must be >= 1 (use null for unbounded pools)"`), empty label sets, and duplicate canonicalized label sets. Also exposes the hot-reload helpers: `config_path()` (env-or-default lookup), `reload_runner_pools(path)` (narrow-schema reload returning `Result<Vec<RunnerPoolCapacity>, ReloadError>`, inherits the same `Deserialize` strictness), and `ScalarSnapshot::{from_config, diff}` (startup snapshot used by the watcher's scalar-drift warn-log). |
| `config_watcher` | Hot-reload watcher task. `spawn_config_watcher(path, app_state, startup_scalars, metrics, shutdown) -> Option<JoinHandle<()>>` watches the parent directory of `$ATC_CONFIG_FILE` via `notify-debouncer-full` (500 ms debounce, non-recursive), reloads via `config::reload_runner_pools` on each debounced event, performs the equality check + atomic replace under the `AppState::runner_pool_capacities` write guard (TOCTOU-safe), and broadcasts `ConfigEvent::{Update, ReloadError}` on `AppState::config_events_tx`. Returns `None` (warn log) when the parent dir is absent — dev boxes without `/etc/atc/` still boot. Owns the `ConfigWatcherMetrics` registration (`atc_config_reload_total{result,reason}` cached counter + `atc_config_runner_pools` observable gauge over `Arc<AtomicI64>`). |
| `routes` | HTTP route handlers: webhook ingestion, REST state snapshot, WebSocket upgrade, health/ready probes. `state_handler` reads from `PersistentStore::read_snapshot`, takes a short `read().await` on `AppState::runner_pool_capacities`, and composes the slice onto the response so the wire payload includes operator config alongside event-derived state. |
| `state` | `AppState` struct only. The broadcast envelope `CommittedEvent` and the REST baseline `StateSnapshot` live in the `atc-wire` crate (ADR 0008). `StateSnapshot` carries a `runner_pool_capacities: Vec<RunnerPoolCapacity>` field annotated `#[serde(default)]` for rolling-deploy tolerance; the field is composed onto each response in `routes::state_handler` from `AppState::runner_pool_capacities` (now `tokio::sync::RwLock`-wrapped so the watcher can replace atomically), **not** by the store. WS subscribe seam moved to `persist.subscribe()` per ADR 0006. AppState also carries `config_events_tx: broadcast::Sender<ConfigEvent>` for the watcher → WS bridge. |
| `ws` | WebSocket upgrade handler. Subscribes to both `state.persist.subscribe()` (committed channel) AND `state.config_events_tx.subscribe()` (config channel). Per-connection select loop wraps each incoming event in a `WireFrame` (outer `kind` discriminator: `Committed` / `ConfigUpdate` / `ConfigReloadError`, defined locally in this module with `tag = "kind"` and ts-rs export). Lagged on either channel closes the socket symmetrically — client reconnects + re-fetches `/v1/state`. |
| `assets` | rust-embed static file serving with SPA fallback and dev proxy to Vite |
| `otel` | OTel SDK initialization: tracer + meter providers (OTLP/HTTP), `TraceContextPropagator`, base-2 exponential histogram view, sampler env-var parsing, provider shutdown helper. The global meter provider installed here is the one every emit site resolves through. Wired at startup; flushed at shutdown. |
| `metrics` | OTel metric registration helpers that stay server-side: `register_build_info` (one-shot startup gauge) and `spawn_process_collector` (wraps `opentelemetry-system-metrics::init_process_observer` in a `ProcessCollectorHandle`). `from_join_handle` is now `#[cfg(test)]` (unit-test-only). The PG-mode `PgMetrics` surface (cached OTel `Counter`/`Gauge`/`Histogram` instruments plus pre-built `[KeyValue; N]` attribute slices for every `atc_pg_*` emit site) lives in `atc-store-pg::metrics` and is owned by `PgStore`. All emit sites resolve through the OTel global meter installed by `otel::init_otel`. See `docs/architecture/metrics.md` for the canonical surface, the authoring contract, and the cached-instrument convention. |
| `shutdown` | Cooperative shutdown orchestration: joins WS handlers, axum serves, then `persist.shutdown()` (which delegates the per-task join budget into the store crate that owns those tasks — listener+drain+heartbeat+sweep in PG mode via `atc-store-pg`; eviction in in-memory mode via `atc-store-mem`), then the config_watcher task (bounded by `SHUTDOWN_TIMEOUT_CONFIG_WATCHER`, 1 s) when armed, then the process metrics collector, then flushes the OTel providers via `otel::shutdown`. Owns the non-store budgets (`SHUTDOWN_TIMEOUT_WS`, `_SERVES`, `_METRICS`, `_CONFIG_WATCHER`); PG-task budgets live in `atc_store_pg::store`; eviction budget lives in `atc_store_mem`. The emitter-categories comment at `shutdown.rs:202–214` enumerates the four ordered categories (persist tasks → process collector → axum drain → config_watcher) that must join before `otel::shutdown`. `join_with_timeout` (from `atc-persist`) treats `JoinError::is_cancelled()` as a clean exit (logged at `warn`). |

## Contracts

Enforced by implementation and verified by tests. Full detail in `docs/architecture/backend-server.md`.

- **Webhook ingestion (both modes):** HMAC-SHA256 verification (when secret configured), parse via atc-github, then dispatch through `state.persist.apply_*_event(env).await`. Returns `{"status":"accepted","seq":<u64>}` on success, `{"status":"rejected"}` (200) on `PersistError::InvalidTransition`, 503 on `PersistError::Backend`. (ADR 0005)
- **NOTIFY emission:** Inside the webhook handler transaction (after outbox INSERT, before commit), `SELECT pg_notify('atc_outbox', seq::text)` emits the outbox row's seq to all listeners. PG queues NOTIFYs during a txn and delivers on COMMIT; aborted txns silently drop. Metric: `atc_pg_notify_emitted_total{kind}`.
- **Drain pipeline:** Listener registers NOTIFY-arriving seqs into `min_pending_seq` for gap-healing. Drain wakes on signal or 5s heartbeat tick, swaps the backstop, computes `pass_start_floor = watermark.min(backstop.saturating_sub(1))`, fetches outbox rows ordered by seq (paginated, batch size 500), deduplicates via 2048-entry ring buffer, broadcasts to subscribers, advances `broadcast_watermark`. On failed pass, re-registers the captured backstop and does not refresh the heartbeat (so `/readyz` reflects sustained drain failure after 30s). Sole broadcaster in PG mode.
- **Seq ordering:** In-memory mode acquires `Mutex<u64>` BEFORE apply + seq assignment + broadcast (strictly monotonic, resets to 0 on restart). PG mode draws ordering from outbox `BIGSERIAL` plus drain's ascending ORDER BY.
- **Broadcast semantics:** Bounded channel (capacity 256). When a subscriber falls behind and the channel buffer overflows, `RecvError::Lagged` is returned. The WS handler closes the connection on `Lagged` (logs a warning, then breaks the loop) — the client reconnects and fetches `/v1/state` to re-establish its seq cursor. This prevents a permanently gapped event stream on the client side.
- **State snapshot (PG mode):** `PgStore::read_snapshot` loads its owned `broadcast_watermark` Arc via `Ordering::Acquire` BEFORE opening a REPEATABLE READ transaction reading runs (`WHERE placeholder=false`) and jobs. The cursor is monotonic in commit order; the frontend tolerates `entity_count >= last_seq` (snapshot may include commits the drain hasn't yet broadcast). Placeholder stub runs are excluded.
- **State snapshot (in-memory mode):** `InMemoryStore::read_snapshot` holds its internal seq `Mutex<u64>` across the snapshot read and seq read. `lastSeq=0` is the cold-start sentinel.
- **State snapshot operator-config layer:** `StateSnapshot.runner_pool_capacities` is composed by `routes::state_handler` after `persist.read_snapshot()` returns, cloning from `AppState::runner_pool_capacities` (built once at startup from the validated YAML config). The `PersistentStore` trait does NOT surface config — it owns event-derived state only. Field is `#[serde(default)]` so a client decoding a snapshot from a replica that lacks the field falls back to `[]` and the frontend merge becomes a no-op (rolling-deploy tolerance).
- **Liveness check (`/readyz`):** Dispatches through `state.persist.liveness_check().await`. `PgStore` returns `Err(LivenessError::DbUnreachable(e))` on `SELECT 1` failure, `Err(LivenessError::DrainStale { age_ms })` when drain heartbeat is > 30 s old, otherwise `Ok(())`. Both the heartbeat refresh (in the drain loop) and the staleness comparison (here in `liveness_check`) read wall-clock through `PgStore.clock: Arc<dyn Clock>`, so tests can drive the staleness path deterministically by advancing a `TestClock` — see `tests/integration/pg_clock_seam_tests.rs` and `readyz.rs`. `InMemoryStore` always returns `Ok(())`.
- **PG access:** No longer on `AppState`. `PgStore` owns its own pool, broadcast sender, `broadcast_watermark`, `last_drain_pass_at`, and the spawned listener+drain `JoinHandle`s (ADR 0006). `atc_pg_write_failures_total{kind=parity|transient}` and `atc_pg_notify_emitted_total{kind}` are emitted from `PgStore::apply_*_event`.
- **WebSocket:** Clean disconnection — no crash, no effect on other clients.
- **Config:** `ATC_GITHUB__WEBHOOK_SECRET` loads `webhook_secret`. If `None`, HMAC verification is skipped.
- **OTel pipeline gating:** When `OTEL_EXPORTER_OTLP_ENDPOINT` is unset, `init_otel` returns `None` and no provider, exporter, or background task is initialized — the OTel global meter provider stays at the SDK's no-op default and every instrument built against it is a no-op. When set, `init_otel` builds OTLP/HTTP tracer + meter providers, installs `TraceContextPropagator` globally, registers the shared `exponential_histogram_view` (so all histograms emit as base-2 exponential aggregations), and sets both providers as the OTel globals. All `register_*` calls and instrument constructions run unconditionally; under the no-op meter they are cheap.
- **Spans:** boundary instrumentation lives in `routes::webhook_handler` (`webhook.handler`, root, manually constructed so `traceparent` extraction can attach the parent context before entry), `atc_github::webhook` (`webhook.verify`, `webhook.parse`), `atc_store_pg::store::writes::PgStore` / `atc_store_mem::InMemoryStore` (`persist.apply.run_event`, `persist.apply.job_event`, `persist.notify.emit`, `eviction.sweep`), `atc_store_pg::listener` (`listener.recv`, `drain.pass`, `drain.broadcast`), and `atc_store_pg::store::retention` (`outbox.heartbeat.tick`, `outbox.sweep.tick`). The long-lived background tasks (`spawn_listener_task`, `spawn_drain_task`, `InMemoryStore::spawn_eviction`, `spawn_outbox_heartbeat`, `spawn_outbox_sweep`) deliberately have no task-lifetime root: each per-tick handler is decorated with `#[tracing::instrument(...)]` directly, so every tick becomes its own root span that exports on completion. A `.instrument(span)` wrapper at the spawn site would never close under normal operation and would lose the span entirely on SIGKILL/OOM — see `docs/architecture/metrics.md` § "Task-lifetime root spans are an anti-pattern". `drain.broadcast` remains a child of `drain.pass` because the `info_span!("drain.broadcast").in_scope(...)` block runs inside the `drain.pass`-instrumented function. Span names + attributes are documented in `docs/architecture/metrics.md` § "Span inventory".
- **OTel SDK shutdown:** `OtelHandles` returned by `init_otel` flow into `run_shutdown_orchestration` (`shutdown.rs`) and are consumed by `otel::shutdown` AFTER every emitter has joined. The persistent store's background tasks (drain + listener + outbox heartbeat + outbox sweep in PG mode; eviction in in-memory mode) are joined together via `persist.shutdown()`; the process collector and axum graceful-shutdown drain are joined separately. The "no live emitter when shutdown fires" invariant is documented in a comment block in `shutdown.rs` enumerating the emitter categories; new emitter categories MUST extend that comment so the join chain stays accurate.
- **OTel env-var contract:** `init_otel` reads the spec-standard envs directly — `OTEL_EXPORTER_OTLP_ENDPOINT` (gates init; HTTP/protobuf only), `OTEL_SERVICE_NAME` (resource attribute, defaults to `"atc"`), `OTEL_RESOURCE_ATTRIBUTES` (auto-extracted by the SDK builder), `OTEL_TRACES_SAMPLER` and `OTEL_TRACES_SAMPLER_ARG` (parsed manually because the SDK's autoload is incomplete on the 0.31 line). Accepted samplers: `always_on`, `always_off`, `traceidratio`, `parentbased_always_on` (default), `parentbased_always_off`, `parentbased_traceidratio`. For ratio samplers (`traceidratio` / `parentbased_traceidratio`), a missing or empty `OTEL_TRACES_SAMPLER_ARG` defaults to `1.0` per OTel spec — selecting a ratio sampler with no arg samples everything, NOT silently falls back to the default sampler. An explicitly-present-but-invalid arg (out of range, unparseable) does fall back to the default with an `eprintln!` warning. Unknown sampler names also fall back; never aborts startup. (Pre-init failures use `eprintln!` rather than `tracing::*` because `init_otel` runs BEFORE `init_tracing_subscriber` — the subscriber is composed with the tracer returned from this call, so any tracing macro fired here would dispatch to the no-op global subscriber and silently disappear.) `OTEL_EXPORTER_OTLP_PROTOCOL` is NOT honored — gRPC is out of scope.

## Testing

```bash
cargo nextest run -p atc-server # tests across four tiers (route-level oneshot, full-stack ephemeral, in-memory store, PG-backed)
cargo clippy -p atc-server -- -D warnings
```

**Docker required.** PG-backed integration tests boot a single shared PostgreSQL container (`atc-test-pg`) via testcontainers with `ReuseDirective::Always`; each test creates its own ephemeral database. Run `just cleanup-test-pg` to reclaim the container and accumulated `test_*` databases.

macOS/OrbStack users: export `DOCKER_HOST=unix://$HOME/.orbstack/run/docker.sock` before running tests.

Tests that read the in-memory metric or span exporter MUST be marked `#[serial_test::serial]`. The OTel global state — tracer provider, meter provider, propagator — is process-wide just like the prior Prometheus recorder was, and `force_flush()` + `get_finished_*()` is non-atomic across concurrent tests (one test's flush would surface another's emissions). A `OnceLock`-guarded harness in `tests/integration/common/mod.rs` installs an `InMemorySpanExporter` + `InMemoryMetricExporter` exactly once per test binary.

Test tier organization is in `docs/architecture/backend-server.md` § Testing.
